# Agent Note: 便携智能体 U 盘产品

Status: proposed

[English](2026-09-11-portable-agent-usb-product.md) | 中文

## 问题

DeepSeek Harness 可以从源码运行，也可以作为打包后的 Desktop 应用或通过平台专用可执行载体运行，但它没有定义一种低成本可移动介质产品，让用户能够免安装运行、安装后脱离介质使用、修复已购安装，并通过介质上的文件复现自身构建。仅复制当前 checkout 无法实现这些目标：依赖树包含平台专用原生文件和绝对链接，构建需要未提交的工具与缓存，持久状态依赖 FAT 和 exFAT 无法一致提供的文件系统行为。

目标产品是由大学生低利润维护、通过非正式交易平台出售的学习交流作品。它需要诚实且有限的承诺，不需要企业许可证、持续更新基础设施、昂贵的发布签名、任意项目支持，也不保证模型完成每项任务。

首个协议与载体里程碑已在私有 `apps/portable` 工作区实现，并记录于[便携产品元数据与 SEA 载体](../../implemented/architecture/2026-09-11-portable-product-metadata-and-sea-carrier.zh.md)；启动器与免安装运行记录于[便携启动器与状态位置](../../implemented/architecture/2026-09-13-portable-launcher-and-state-location.zh.md)；构建发行版所携带 Runtime 的命令记录于[便携 Runtime 构建路径](../../implemented/architecture/2026-09-13-portable-runtime-build-path.zh.md)；启动器的状态根选择记录于[便携状态根选择](../../implemented/feature/2026-09-16-portable-state-root-selection.zh.md)；发行方品牌与精简消费组合记录于[发行方品牌与消费端组合](../../implemented/architecture/2026-09-12-publisher-branding-and-consumer-composition.zh.md)。本记录描述的安装与修复流程、介质工具、离线 DevKit 和销售资格仍处于提案阶段。

## 提案

基于 DeepSeek Harness 创建使用独立名称的非官方便携智能体 U 盘产品。发行方通过集中式产品配置替换名称前，暂用工作名 **便携智能体实验盘**。产品文案必须说明 DeepSeek 不发布或背书该产品，并标明准确的上游源码 revision。

开发过程使用可独立验证的里程碑，但不把任何里程碑作为未完成产品出售。发行方只出售满足完整发布验收条件的构建。每次出售的是固定最终版本，不提供更新服务，也不承诺与后续内容兼容。

### 产品模式

一个制作完成的介质通过小型本地启动器提供以下受支持模式：

- **便携运行**无需安装即可启动打包后的 Harness，并把便携状态存入介质拥有的 Harness home。
- **当前用户安装**无需管理员权限，把产品安装到当前用户的本地应用目录，创建正常启动与卸载入口，并在移除介质后继续工作。
- **校验与修复**验证已购版本的 manifest，并且只恢复该版本的程序文件。修复会保留工作区、会话、设置和凭据；只有用户在备份后选择经过单独说明的重置操作时，才会修改这些数据。
- **备份与导入**在便携 home 与安装 home 之间显式复制受支持的用户数据。产品不会自动同步两个 home。
- **开发者材料**把源码、补丁、许可证、离线依赖和重建说明放入独立的 `Developer/` 目录，普通用户界面不宣传该目录。

启动器还提供中文指南、产品身份、上游归属、许可证、第三方声明和完整性结果。它不提供更新、回滚、品牌编辑或任意插件安装操作。

### 平台与介质

首个版本支持 x64 架构的 Windows 10 和 Windows 11。分发目录使用平台适配器以及 `Runtime/<os>-<arch>` 和 `Developer/<os>-<arch>` 根目录，使后续工作能够添加原生 macOS 或 Linux 产品，而无需重新定义 manifest、启动器协议或产品配置。首个版本不携带，也不承诺 macOS、Linux 或 Windows arm64 产物。

实体产品的基线是经过验证的 16 GB USB 3.0 设备，并格式化为 NTFS。产品不要求高端或高速型号。介质制作必须测试标称容量、回读每个写入字节、拒绝损坏或扩容设备，并为用户数据和一份修复副本保留足够空间。低速或不兼容介质可以把不可变运行时文件暂存到宿主机私有目录，但启动器必须披露此模式，并在正常退出后清理其自有文件。制作工具必须先生成并验证 staging 目录，再接收用户明确选择的可移动卷目标；它绝不自动发现并格式化磁盘。

源码 checkout、单个 `node_modules` 树和单个可写 Harness home 无法跨操作系统移植。各平台的构建缓存和原生依赖必须隔离在对应平台根目录下。FAT 和 exFAT 不受支持作为实时 Windows 工作区或 Harness-home 文件系统，因为默认 Windows sandbox 需要 ACL 行为，持久介质还可能需要链接和持久替换语义。

### 运行时与重建分离

产品把日常使用的 **运行时**与离线 **DevKit** 分开。便携启动和安装启动使用预构建的 Windows x64 运行时，并且不能仅为启动 Harness 而要求系统安装 Node.js 或 Python。实现应复用[单文件可执行运行时](../../implemented/architecture/2026-07-10-single-file-executable-sdk-runtime-distribution.zh.md)或 [Desktop 内置运行时](../../implemented/architecture/2026-09-08-desktop-bundled-runtime-and-external-plugins.zh.md)，但产品专用的已安装产物对比必须先证明哪种载体满足启动器、体积、修复和消费界面要求。

Windows DevKit 携带准确源码、便携 Node.js 和 Python 工具链、pnpm 入口与内容寻址 store、必要构建缓存、经过验证的预构建原生输入，以及在无网络时重建 TypeScript、Web 和可执行产物所需的脚本。普通离线重建可以使用这些经过认证的原生输入。从源码构建每个原生组件属于另一套维护者环境，需要 Python、headers、编译器和平台原生构建工具；消费产品不承诺在任意目标机器上执行该操作。

首个版本声明的任务工具链包括 Git、Node.js 与 TypeScript、Python、PowerShell，以及 Harness 自有的文件搜索。需要其他编译器、容器运行时、SDK、可执行程序、提升权限或在线服务的任务不属于保证执行范围。Harness 可以使用买家配置的模型 endpoint 和网络；离线打包与重建不代表模型推理离线。

### 状态、凭据与隐私

安装模式在宿主机上使用当前用户专用的 Harness home。文件系统受支持时，便携模式使用介质上的独立 Harness home；否则使用明确披露的宿主机 staging home，并在正常退出后导出。安装过程可以提供一次性便携状态导入。后续交换只能通过显式备份或导入操作完成；自动双向同步和冲突解决不在范围内。

买家提供全部模型 API 凭据，并承担全部提供商费用。产品绝不包含发行方的共享密钥，也不通过发行方运营的服务代理模型请求。凭据界面提供加密本地 vault 和不持久保存模式。设计必须说明：凭据解锁后，同一用户权限的进程可以访问它；加密保护的是遗失介质或未使用的存储，而不能防范正在运行的智能体本身。

产品不收集 telemetry，也不自动发送对话、工作区内容、凭据或诊断。售后诊断在本地生成，默认移除秘密和用户内容，并且只有用户显式导出后才离开机器。

### 消费界面与发行方品牌

消费 Web 界面保留对话、项目选择、会话历史、工具调用展示、模型与凭据设置，以及必要偏好。它隐藏插件开发、包管理、品牌编辑、实验性定制和其他高复杂度开发控件。移除可见控件不得从源码中移除底层扩展架构。

一个由发行方拥有的 `product.yml` 和本地资产目录在构建时定义产品标题、Logo、主色、欢迎语、版本、售后声明和上游归属。消费设置不提供该配置。配置必须拒绝脚本、事件处理程序、任意 HTML 或 CSS，以及远程资产 URL。同一构建机制可以制作另一个发行方品牌或联名品牌，而无需修改应用组件；普通买家不能生成品牌包或加载任意 client 代码。

启动器启动由已认证本地 Host 支持的 Web 应用，而不是把 Vite 输出作为独立静态站点提供。默认继续绑定 loopback。静态品牌资产不得包含凭据或私有配置。

### 销售、售后与版本政策

产品收费对象是围绕开源软件提供的实体介质、打包、启动器、经过测试的组合、中文指南和有限售后。每个介质都包含对应源码和本地修改、MIT 许可证、适用的第三方声明、构建 manifest 和 SHA-256 checksum。产品文案不得暗示对 DeepSeek Harness 的独占所有权或与 DeepSeek 的官方关系。

已购构建不提供在线 updater、离线 updater、后台更新检查、A/B 更新目录、账号激活、设备绑定、DRM 或 U 盘加密狗要求。安装后的产品启动时绝不需要原始介质。发行方可以把后续内容作为另一项产品发布，但不对早期版本作出兼容、迁移、折扣或可用性承诺。

简单售后从收货起持续 30 天，范围包括安装、启动、填写买家自己的 API Key、同版本校验与修复，以及文档中的基础流程。如果分发程序存在阻止受支持文档流程的明显缺陷，发行方可以提供同一已购版本的修正版。售后不包括新功能、上游升级、API 费用、模型质量保证、项目专用调试、缺失的第三方工具链、操作系统修复或未备份数据恢复。

首个版本可以不使用公开信任的 Windows 代码签名证书。它必须提供 checksum，在启动前显示准确的产品和上游版本，并说明 Windows 未知发布者警告，但不得指示用户关闭平台安全功能。产品不把自签名证书描述成第三方信任。商业签名仍是可选发布决定，而不是架构要求。

### 拟议分发目录

具体名称可以在实现期间调整，但文件所有权必须保持分离：

```text
/
  Launcher.exe
  product.yml
  manifest.json
  manifest.sha256
  Runtime/win-x64/
  Recovery/win-x64/
  Source/
  Developer/win-x64/
  Docs/zh-CN/
  Licenses/
  PortableData/
```

不可变程序、恢复文件、源码、文档和许可证文件由 manifest 拥有。`PortableData/` 由用户拥有，并排除在程序修复之外。宿主机安装程序文件和安装用户状态分别归属不同 owner，因此卸载与修复不能根据任意持久路径推导破坏性目标。拟议的 [Desktop 卸载保留规则](2026-09-08-desktop-uninstall-preserve-dsh-home.zh.md)仍是独立输入；本提案既不实现也不取代该规则。

### 实现顺序

上述协议与载体里程碑已经完成顺序项 1，品牌与消费端组合里程碑已经完成顺序项 2；第 3 至第 7 项仍处于提案阶段。

1. 记录产品配置 schema、分发 manifest、文件系统归属规则、威胁限制和验收测试框架。**已实现。**
2. 添加发行方品牌和精简消费组合，同时不更改底层 client 扩展 contract。**已实现。**
3. 添加 Windows 启动器、便携运行、当前用户安装、卸载和显式状态根选择。启动器、便携运行与显式状态根选择已实现；当前用户安装与卸载流程尚未实现，尽管它们所要消费的安装记录、ASCII 安装目录名、注册表卸载项，以及删除目标防护均已写好。
4. 添加全介质制作、完整性校验、备份、同版本修复和恢复行为。
5. 添加凭据 vault、不持久保存凭据流程、脱敏诊断导出和显式数据导入导出。
6. 组装并验证 Windows 离线 DevKit 及其普通重建路径。
7. 生成 staging 后的 U 盘分发包，执行干净机器发布验收，并在出售前完成简体中文指南。

每个里程碑都包含代码、聚焦测试、仓库规则要求的用户可见 snapshot、文档和可复现实证。里程碑是内部开发检查点，不是可出售版本。

## 考虑过的替代方案

**每次启动都从源码构建。**这种方式让普通启动依赖完整编译器与包管理器环境，放大低成本闪存介质的小文件延迟，并且无法提供有限的干净机器承诺。预构建运行时与独立 DevKit 可以同时保留即时使用和可复现性。

**跨 Windows、macOS 和 Linux 复用一个 checkout 与依赖树。**各平台的原生模块、可执行位、链接、sandbox policy 和包管理器路径均不相同。一个实体产品可以包含多个平台根目录，但一个已安装依赖树不能作为跨平台单元。

**把 exFAT 或 FAT 作为实时跨平台文件系统。**这些格式更适合文件交换，但无法满足 Windows ACL sandbox 和全部持久状态链接语义。Windows 版本使用 NTFS，并通过 manifest 保留跨平台结构，而不宣称不受支持的实时便携性。

**要求高端高速介质或 64 GB 容量。**已经确认的产品以低成本为目标。经过验证的 16 GB USB 3.0 设备加可选宿主机 staging 是基线；设备是否可用由发布验收决定，而不是营销速度等级。

**开放原版开发和定制界面。**普通买家需要受支持的任务流程，而不需要插件开发、任意 JavaScript 或品牌工具。隐藏这些控件可以减少意外代码执行和售后负担，同时源码仍可通过 `Developer/` 获取。

**共享发行方 API Key 或运营代理服务。**两种选择都会产生不可控成本、秘密暴露、隐私义务和持续运维。买家直接使用自己的提供商账号。

**出售前加入企业激活、硬件加密狗、持续更新和公开信任签名。**这些系统的建设与运营成本超出低利润学习产品的合理范围。固定版本、透明源码、确定性 manifest、简单修复和有限售后符合预期销售方式。

**自动同步安装状态和便携状态。**双向同步会引入冲突、凭据移动、格式耦合和可移动设备中断路径。显式备份与导入让每次数据传输可见且可恢复。

**承诺与后续版本兼容。**DeepSeek Harness 处于开发者预览阶段，持久格式会演进。每个固定产品版本独立存在；后续内容不附带旧版本兼容或迁移承诺。

## 验收标准

- 没有系统 Node.js 或 Python 的干净 Windows 10 和 Windows 11 x64 普通用户环境可以校验介质并启动便携模式。
- 同一环境可以为当前用户安装产品、移除介质、重新启动已安装产品并完成卸载，且不会删除用户工作或独立拥有的 Harness home。
- 买家可以配置个人模型 API Key，选择不持久保存，并在凭据缺失、被拒绝或无法访问时看到明确错误。
- 便携模式和安装模式可以创建或打开 Git 工作区、读写文件，并调用声明的 Git、Node.js/TypeScript、Python 和 PowerShell 工具。
- 重启某种模式会恢复已提交会话。显式备份与导入会报告来源、目标、冲突、排除的秘密和完成状态，而不会自动同步。
- 校验可以检测 manifest 所有文件的缺失或变化。同版本修复会恢复不可变程序内容，同时逐字节保留用户拥有的工作区、会话、设置和凭据。
- 发行方可以在发布构建中修改每个 `product.yml` 字段和本地品牌资产，而无需编辑应用组件。消费界面不提供这些字段，也不能加载任意 client 代码。
- 网络不可用时，Windows DevKit 可以通过随盘源码和经过认证的原生输入重建声明的 TypeScript、Web 和可执行产物。另一项维护者检查负责完整的原生源码构建。
- 介质制作会验证一个 16 GB 目标，只写入明确选择的可移动卷，复制后验证每个 manifest 所有字节，并且在目标空间不足、损坏或不符合预期时拒绝继续，而不会格式化另一块磁盘。
- 修复、空间不足、盘符变化、低速介质 staging、复制中断、意外移除和不支持工具等失败会产生本地化说明与恢复操作。任何测试都不得宣称意外移除可以保留尚未 flush 的工作。
- 发布包包含对应源码、修改、构建身份、checksum、许可证、第三方声明、隐私与安全披露、30 天售后范围，以及固定版本且不提供更新的政策。
- 出售前完成完整验收矩阵。只有由 implemented Agent Note 归属的代码和文档才属于当前实现；不能仅因本提案存在就把完整产品视为已经实现。

## 风险

DeepSeek Harness 是开发者预览项目，因此出售前完成产品不能稳定上游 API 或格式。固定版本 fork 可以降低持续售后负担，但会把安全评审、依赖披露和发布验收责任转移给发行方。

未签名 Windows 可执行文件可能触发 SmartScreen 或防病毒警告。Checksum 与源码透明度可以检测内容变化，但不能建立公开信任的发布者身份，也不能保证 endpoint security 接受程序。

低成本可移动介质可能缓慢、扩容或突然损坏。全设备验收和显式备份可以降低概率与影响，但无法恢复唯一副本位于故障设备上的数据。

凭据 vault 只在锁定时保护未使用文件和遗失介质。模型提供商、同一用户权限的进程、已启用工具和运行中的智能体可以观察用户在执行期间授权的数据。

NTFS 使 Windows 产品可靠，但不是跨平台可写介质 contract。后续 macOS 和 Linux 产品需要原生文件系统、签名、sandbox、工具链和干净机器验收，而不能只移植启动器。

内置 Git、Node.js、Python、原生二进制、字体和未来品牌资产分别承担再分发与安全义务。发布 inventory 必须证明许可和 provenance；仅有上游 MIT 许可证不能覆盖每项内置依赖或第三方服务。

精简界面可能隐藏高级买家期待的能力，而独立源码树仍允许他们制作不受支持的派生版本。售后文案必须区分经过测试的消费组合和源码级实验。
